# 面向截图、笔记的插件系统演进设计

状态：内部运行时、原生公开 SDK 与独立示例已实现；尚未发版，界面待验证
日期：2026-10-23
范围：当前仓库源码审查；未进行运行时性能测量

## 1. 建议

继续使用 Qt/C++ 原生模块，将现有命令插件演进为支持独立生命周期的应用模块。优先补齐命令路由、资源懒加载、窗口承载、保存退出和异步任务约定，再接截图、笔记。

现有基础可以保留：命令哈希查找、别名、QHotkey、视图懒创建、待办的业务与存储分层、Qt Test。2026-10-23 已确认 Plugin API 面向客户和第三方开发者，因此独立 SDK、外部加载、版本兼容检查与独立示例属于基座对外可用的必要条件。建议第一版沿用 Qt/C++ 原生路线；脚本引擎、WebEngine 和进程隔离另按需求设计，不阻塞原生 SDK。公开边界与发布验收见 [plugin-api.md](plugin-api.md)。

## 2. 改造前的源码审查记录

下表记录第一轮改造前的行为；当前已完成项与剩余限制见第 9 节。

| 位置 | 当前行为 | 大应用接入时的影响 |
| --- | --- | --- |
| `src/main.cpp` | 启动时逐个 `new` 并注册全部插件 | 无法只登记命令、按需创建插件实例 |
| `src/plugins/TodoPlugin.cpp`、`src/todo/TaskService.cpp` | 待办构造时创建服务并同步读取 JSON | 即使没有打开待办，启动也会加载其数据；复制给笔记后成本会放大 |
| `src/plugins/IPlugin.h` | 一个接口同时负责命令、查询、动作、页面和设置 | 默认值减少了实现负担，但缺少多命令身份、执行状态、窗口及关闭契约 |
| `src/plugins/PluginManager.cpp` | 用命令与别名直接映射到实例；`commands()` 包含别名 | 设置页、快捷键注册各自通过指针集合去重；插件身份与入口耦合 |
| `src/MainWindow.cpp` 的 `openPluginView()` | 页面放进 `QStackedWidget`；进入时高度重设为 460 | 没有独立窗口、全屏覆盖层或每个应用的窗口偏好契约 |
| 同文件的 `launchCurrent()` | 动作返回 `true` 后统一 `hide()` | 无法表达保持窗口、打开文档、开始异步任务等不同结果 |
| 同文件的 `activateCommand()` | 快捷键先显示主窗口、填写命令，再分流 | 截图快捷键会先经过启动器，不适合直接截取当前桌面 |
| `IPlugin::queryResultsChanged()` 与 `MainWindow` | 信号只有查询字符串；宿主仅对 `file` 接线 | 笔记全文检索等异步查询还需修改宿主，字符串也不足以唯一标识一次查询 |
| `src/plugins/FilePlugin.cpp` | 单个后台搜索，只保留最新待查词；取消会清理请求与结果 | 已有过期结果过滤，但不一定中止正在执行的 SDK 调用 |
| `IPlugin` 与 `MainWindow` | 无统一激活、停用、释放、退出准备约定 | 已打开的页面留在堆栈；隐藏不等于释放；后台任务归属不明确 |
| `src/todo/TodoView.cpp` | 用 `hideEvent()` 刷新编辑内容 | 已有保存保护，但宿主无法等待保存完成，也不能因保存失败阻止离开 |
| `src/plugins/PluginManager.cpp` | 查询和启动模式检查启用状态，直接取视图、执行动作未统一检查 | 禁用插件后，直接打开视图或旧动作仍可能到达插件；当前测试未覆盖这些入口 |
| `CMakeLists.txt`、`src/plugins/ConvertPlugin.cpp` | `typego_core` 链接 Widgets，换算逻辑与视图在同一文件 | 无窗口测试仍可运行，但纯逻辑层尚未与界面实现彻底分离 |

主窗口还统一处理失焦隐藏、Esc 和窗口级方向键、Ctrl+N、Ctrl+P。笔记的新建快捷键、编辑器按键和截图取消操作应有各自作用域；这些具体交互需要本机验证，目前不能断言全部存在冲突。

现有结果模型首批展示 80 条、后续每批 120 条，但查询已先生成完整结果列表。这属于分批展示，并不是存储层分页。Qt 容器有隐式共享，不能将多次列表赋值直接当作深复制；应通过测量定位成本，优先减少完整结果物化、逐项 map 构造和分离时的复制。

## 3. 把插件身份、命令和运行实例分开

新增轻量 `PluginDescriptor`，启动时仅登记元信息及工厂：

- 稳定 `pluginId`、名称、描述、图标、设置入口能力。
- 命令列表；每条命令有独立 `commandId`、输入词、别名、描述和默认呈现方式。
- 一个创建实例的工厂，首次查询或显式执行时才调用；实例构造仍应轻量。

例如笔记应用可提供 `note`、`note-new` 两条命令；截图应用可提供 `shot`、`shot-history`。这些是同一应用的不同操作，不能只当作等价别名。

管理器维护两张表：`pluginId → descriptor/instance`、`命令词 → pluginId + commandId`。设置页枚举 descriptor，快捷键绑定命令，均不应为了显示名称而创建实例。现有快捷键设置按主命令存储，迁移时映射到默认命令，保留用户原值。

从列表、快捷键、托盘进入时，都构造同一种 `Invocation`，包含插件 ID、命令 ID、参数、来源及必要的对象 ID。查询只是提供建议；截图、创建笔记等副作用必须发生在明确执行后。

所有调用先经过同一处可用性检查，覆盖查询、执行、视图、快捷键和异步结果接收。禁用已运行的应用需要先完成保存和任务收尾；收尾失败则报告并保留应用，不应只改开关后强制销毁。

## 4. 查询、执行、界面分别表达

不要求每个插件实现同样多的虚函数。保留最小模块接口，按需增加查询、界面和生命周期能力；第一阶段可以用适配器兼容现有 `IPlugin`，避免一次重写所有插件。

### 查询

`QueryRequest` 包含递增请求 ID、参数、结果上限和可选分页游标；响应携带相同请求 ID、结果及状态。

- 简单计算直接返回；文件和笔记搜索允许后台返回。
- 宿主同时核对请求 ID、插件启用状态和当前查询会话，旧结果不能覆盖新结果。
- 取消优先采用协作式令牌；不能中断的底层操作允许完成，但结果必须丢弃。
- 限制并发和排队长度；不能每次按键都新建线程或积压搜索。
- 分批追加要保留选中项，以稳定结果 ID 定位，避免每次完成都重置到第一项。

### 执行

用明确结果替代 `bool`，至少区分成功、失败、执行中，并单独指定宿主行为：保留启动器、隐藏启动器、打开应用界面。异步执行返回操作 ID，后续完成、失败或取消均关联该 ID。

这样“复制计算结果并隐藏”“新建笔记后继续编辑”“开始截图并等待选择”可以共用路由，而不需要宿主判断具体插件名。

结果项可逐步采用强类型轻量结构，包含稳定 ID、标题、摘要、图标引用、动作 ID 和小型参数；过渡阶段在宿主边界转换现有 `QVariantMap`。全文、图片原始数据和编辑器状态不应放进搜索结果或动作 map。

### 界面

呈现方式与查询方式解耦，支持：

| 呈现方式 | 用途 | 宿主职责 |
| --- | --- | --- |
| 列表 | 计算、文件、笔记搜索建议 | 搜索输入与结果选择 |
| 嵌入页 | 设置、换算、现有待办 | 返回导航、页面容器 |
| 独立窗口 | 长时间笔记编辑、截图历史 | 窗口注册、激活、几何恢复、退出协调 |
| 全屏覆盖层 | 截图选择与标注 | 捕获前窗口处理、焦点和取消恢复 |

简单插件可以没有界面。一个应用也可以同时提供搜索列表和独立窗口。笔记优先设计独立可调整窗口，以便编辑时仍可唤起 TypeGo；待办暂时保留嵌入页，验证承载机制后再决定是否增加独立窗口。

窗口创建时明确所有者：嵌入页由宿主容器管理，独立窗口和覆盖层由应用窗口管理器登记并负责销毁，插件保存 `QPointer` 等观察引用。创建接口接收明确父对象，替换当前含义不准确的 `viewUrl()`。先约定每个应用一个主工作窗口，笔记的多文档使用标签页或文档 ID，不急于引入任意多窗口。

主窗口列表导航快捷键只在结果页生效。应用窗口各自处理编辑快捷键、Esc 和焦点；失焦是否隐藏按呈现方式确定，不能让笔记编辑窗口继承启动器的自动隐藏行为。

## 5. 生命周期和退出保存

分别管理模块、业务服务、文档会话和界面；不能把所有资源都绑到一个 QWidget。

建议约定：首次需要时初始化；进入界面时激活；离开时停用；空闲时尝试释放缓存或页面；禁用与应用退出前执行退出准备。打开查询建议不应自动创建编辑器或全屏覆盖层。

退出准备返回“可离开、拒绝、等待完成”，并带离开原因：返回列表、关闭应用窗口、禁用插件、退出 TypeGo。异步保存期间合并重复离开请求；完成后继续原操作。写入失败保留编辑会话并允许重试。

隐藏页面不代表保存成功，关闭界面也不代表应立即停止全部服务。笔记保存或索引、shell 进程应有明确继续或取消策略。存在编辑内容或运行任务时禁止空闲回收；可重建的视图和缩略图缓存优先回收。

TypeGo 的托盘退出和重启目前直接调用退出，应一起纳入协调。正常退出先等待待保存内容和必要任务收尾，再销毁窗口、插件和服务。不能只依赖 `aboutToQuit` 启动异步保存，因为届时事件循环即将结束；强制终止场景依靠已落盘草稿恢复。

## 6. 宿主提供少量公共能力

按需注入数据目录、配置访问、窗口管理及任务取消能力。第一轮不要做包含所有对象的全局服务定位器，也不要创建通用插件事件总线。全局快捷键继续复用 `third_party/QHotkey`。

每个插件使用稳定 ID 划分配置与数据空间，例如 `plugins/<id>/`，正文与附件由业务模块决定存储方式，临时文件和可丢弃缓存单独存放。已有 `todo.json` 和插件设置需要显式兼容，不能直接改路径导致旧数据“消失”。业务服务继续支持注入临时路径，测试不碰用户数据和注册表。

截图插入笔记先定义小型附件引用：文件或资源 ID、媒体类型、尺寸和所有权。持久插入前由笔记接管附件，或使用明确的共享持久存储，不能长期引用可能被清理的截图临时文件。取消插入时清理尚未接管的临时资源。

## 7. 两类新应用如何接入

### 截图

调用链：快捷键或确认命令 → 统一执行路由 → 处理 TypeGo 可见窗口 → 捕获屏幕 → 覆盖层选择/标注 → 保存、复制或转交附件 → 清理会话。

- 截图快捷键可以直接执行，不先弹启动器。执行请求记录此前窗口与焦点，完成或取消按来源恢复。
- 捕获前隐藏会进入画面的 TypeGo 窗口，包括启动器、相关浮窗；覆盖层在屏幕捕获后创建。具体范围由截图功能定义。
- 不能将现有失焦处理的 50ms 延时当作“桌面已经重绘”的保证；捕获后端需要验证窗口消失与桌面合成时序。
- 多屏负坐标、逻辑坐标与物理像素、混合 DPI、屏幕变化都在截图模块处理。宿主只协调流程。
- 图像格式转换、编码和历史缩略图允许后台执行；GUI 对象和屏幕捕获按后端线程要求操作。
- 原图尽量共享只读数据，裁剪和标注按需生成；缓存设置字节预算，结束会话释放全屏图像。

一张 3840×2160 的 32 位图像原始像素约 31.6 MiB，三份独立缓冲约 95 MiB，尚不含 GPU 与编码缓冲。这说明内存优化重点应落在图像生命周期、复制及缓存上，而不是命令哈希查找。上述是尺寸估算，不是当前程序测量值。

### 笔记

调用链：`note` 查询摘要或打开工作区；`note-new` 直接创建文档；选中结果通过文档 ID 打开已有笔记。

- 列表只读取标题、摘要、更新时间等必要字段；打开文档才加载正文与附件。搜索结果上限和存储分页分别处理。
- `NoteService` 管理文档与保存，`NoteRepository` 管理存储，编辑器只维护当前会话与交互；规则放进可测试的纯逻辑层。
- 防抖保存加草稿恢复；每次保存携带文档修订号，旧写入完成不能覆盖新内容。关闭时刷新最新修订，失败保留文档。
- 避免沿用“每次修改序列化全部数据”的存储方式。正文按文档写入；全文索引可重建，附件独立存放。
- Markdown 文件与 SQLite 的选择等内容格式、检索需求明确后决定；无需为了插件框架提前绑定一种存储。
- 编辑器、预览器、全文索引分别按需创建，未使用笔记时不读取全部正文或启动索引任务。

## 8. 建议实施顺序

每项独立提交，保持现有插件可用。SDK 公共接口与内部适配分离、插件包发现及按需加载、API/ABI 校验，以及只依赖安装后 SDK 的独立工程验证现已实现。对外接入闭环属于基座完成条件，客户无需修改宿主源码。

1. **统一插件登记与入口检查**：增加 descriptor、稳定 ID、工厂和独立命令表，保留旧接口适配；设置页和快捷键改读元信息，待办服务按需创建。补齐禁用插件无法直接打开视图或执行旧动作的测试。完成后，新增应用不会因展示名称和设置项而初始化。
2. **统一执行和窗口生命周期**：增加 Invocation、执行结果、界面承载与离开准备；将主窗口分流逻辑移到独立宿主控制器。用现有待办验证保存、返回、禁用和退出；确认独立窗口不会继承启动器失焦隐藏。
3. **统一异步查询**：用请求 ID、取消和结果上限替换 `file` 专用接线；迁移 Everything 搜索，同时保留其全局 SDK 状态串行约束。将换算规则与 QWidget 实现分开，收紧纯逻辑层边界。
4. **接入截图最小闭环**：直接快捷键、区域选择、复制/保存、取消恢复、多屏 DPI 与图像释放；历史和 OCR 后续独立加入。
5. **接入笔记最小闭环**：独立工作区、文档搜索、编辑保存、草稿恢复和截图附件；后续再做高级格式、同步等能力。

第一步就能改善启用语义和启动资源使用；第二、三步完成后，再加大应用不会继续扩散 `MainWindow` 中的插件名称判断。

## 9. 验证方式

改造前先记录同一机器与构建配置下的冷启动、暖启动、空闲私有内存，以及首次打开待办、关闭后的内存；测量期间区分应用扫描、更新检测等背景活动，避免归因错误。后续同口径比较，不提前承诺未经测量的性能百分比。

Qt Test 重点覆盖：只读元信息不创建实例、工厂只按需执行、命令与别名冲突、禁用入口一致性、旧查询丢弃、取消后不回填、执行结果分流、离开拒绝与异步完成、保存修订顺序、临时数据路径隔离。生命周期决策规则可无界面测试，真实窗口与截图由本机手工验证。

按仓库要求使用 `test.bat` 和 `build.bat`；运行使用 `run.bat`。手工验证包括：快捷键直达截图、画面不含应隐藏的 TypeGo 窗口、取消恢复焦点、多屏混合 DPI、笔记编辑快捷键、保存失败、禁用正在编辑的应用、托盘退出与重启。

2026-10-23 实施进展：已实现元信息与工厂登记、多命令身份、插件与待办服务懒创建、统一入口检查、执行结果与异步完成令牌、窗口宿主、离开准备协议、待办编辑器保存检查，以及通用异步查询。Everything 已迁移，主窗口不再为其异步结果单独接线。设置与快捷键从元信息生成，原配置键保持兼容。

当前窗口宿主每个应用缓存一个界面，不支持同一应用同时打开不同呈现方式；多窗口几何恢复、空闲定时回收、全局异步任务配额、存储分页以及换算逻辑与界面的拆分仍未实施。当前待办离开检查覆盖编辑器待保存内容，业务服务其他操作的落盘失败状态尚未统一纳入。客户端更新安装仍沿用原退出流程，未经过新增的托盘退出协调。相关边界需在接入大型应用前继续补齐。

公开 SDK 增补了独立命名空间与接口、CMake 安装包、元数据/二进制兼容检查、外部包扫描、懒加载适配器、宿主目录/配置/日志服务、结果字段验证和待完成执行上限。客户示例从安装后的 SDK 独立编译，并通过真实 DLL 的隔离加载验证。当前 `test.bat` 的 15 个测试程序通过；真实界面与交互尚未验证，构建和 SDK 分发说明见 [plugin-api.md](plugin-api.md)。内置实现说明见 [plugin-runtime.md](plugin-runtime.md)。
